**Auditability in practice.**
- Every rule and statistical alert carries a check id, the columns, example rows, and the observed
  vs expected value.
- Every LLM verdict is stored with its prompt, answer, tokens and latency in
  `project_b/llm_cache/`, so an auditor can replay and read it. The cache makes the LLM
  reproducible, not deterministic: a fresh call can answer differently, which is why the LLM only
  ever confirms flags a deterministic check raised.
- Personal data (l) always alerts at once, however few rows. The price is accepted: a new 311
  category label can raise a PII alert until the reference vocabulary is refreshed. Ignoring
  capitalisation in category labels would stop that, but would also hide a name written into a
  label, so it was not adopted (RESULTS_B.md section 7).
- An LLM reply that cannot be read is an abstention, never a "clean" verdict. In the pipeline a
  value the LLM did not judge keeps its cheap flag, so an unreadable reply can never silence an
  alert.
